# Code Review Patterns

A concise reference for giving and getting better code reviews. It distills the
habits that keep pull requests fast, kind, and high-signal: labeled comments
(nit vs blocker), small focused diffs, critiquing the change instead of the
person, and async review manners.

## When to use it

Pull it up when you are about to open a PR, when your reviews keep stalling, or
when feedback threads turn tense. It works for any team and any VCS host
(GitHub, GitLab, Gerrit, etc.) — the patterns are tool-agnostic.

## What's inside

The full copy-pasteable cheatsheet lives in the snippet
(`snippets/markdown.md`): comment label conventions, sizing guidelines,
phrasing templates, end-to-end workflows, and a gotchas list.
