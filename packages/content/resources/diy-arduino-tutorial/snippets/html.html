03 The sketch

SKETCH-03.INO

Two functions run everything: setup() once at power-on, then loop() forever. Callouts below the editor explain both.

blink_button.ino 
// Lesson 03 — Blink + Button
// Board: NV-UNO R3 (UNO-compatible) · IDE 2.x

const int LED_PIN = 13;  // through R1 (220Ω)
const int BTN_PIN = 2;   // tactile button SW1

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BTN_PIN, INPUT_PULLUP);  // no external resistor!
  Serial.begin(9600);
}

void loop() {
  // pull-up means: pressed = LOW, released = HIGH
  if (digitalRead(BTN_PIN) == LOW) {
    digitalWrite(LED_PIN, HIGH);
    Serial.println("SW1 pressed");
  } else {
    digitalWrite(LED_PIN, LOW);
  }
  delay(10);  // crude debounce — Lesson 04 does it properly
}
L07–L11 · setup()

Runs once when the board powers up or resets. Here we declare pin directions and open the serial port. INPUT_PULLUP switches on an internal ~20 kΩ resistor so the pin idles at HIGH instead of floating randomly.

L13–L23 · loop()

Repeats forever, thousands of times per second. Because of the pull-up, a pressed button reads LOW — the logic looks inverted but is completely normal. The delay(10) softens contact bounce for now.

05 Troubleshooting

FAQ-L03

  • Polarity first. Flip the LED — 9 times out of 10 it's in backwards. It won't be damaged.
  • Confirm R1 and the LED anode share the same breadboard row (the column rule).
  • Swap wire W1 to pin D13 — a neighbor pin off-by-one is a classic.

  • SW1 is probably rotated 90°. The 4 legs bridge in pairs — rotate it so pins 1/2 sit on opposite sides of the center gap.
  • Verify the sketch uses INPUT_PULLUP, not plain INPUT. A floating pin reads garbage.

  • That's contact bounce — the metal contacts chatter for a few milliseconds. delay(10) tames most of it.
  • Lesson 04 replaces the delay with a proper millis()-based debounce that never blocks the loop.

  • Try a different USB cable — charge-only cables have no data lines and are the #1 culprit.
  • On clones, install the CH340 USB-serial driver, then reopen the IDE.
