# Git Bisect — Binary-Search for the Bug

`git bisect` walks your commit history with a binary search to pinpoint the exact
commit that introduced a regression. You mark a known-bad commit and a known-good
commit, then Git checks out the midpoint and asks you to judge it — halving the
search space each step until the culprit is isolated.

## When to use it

- A test or feature worked at some point in the past but is broken now.
- You have a reliable way to tell "good" from "bad" (a manual check or a script).
- The offending change is hidden somewhere in dozens or thousands of commits.

## Why it is fast

Instead of checking every commit, bisect needs only `log2(N)` steps. A range of
1000 commits is narrowed down in about 10 checks — and with `git bisect run` it
can do all of them unattended.
