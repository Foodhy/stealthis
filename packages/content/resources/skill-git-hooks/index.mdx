# Git Hooks — Automate Your Workflow

Git hooks are scripts Git runs automatically at key points in your workflow —
before a commit, when a commit message is written, or before a push. They let you
enforce quality gates (lint, format, tests, message conventions) without relying on
anyone to remember.

## What this skill covers

- The client-side hooks you actually use: `pre-commit`, `commit-msg`, `pre-push`
- Where hooks live (`.git/hooks`) and how to make them executable
- Sharing hooks across a team with `core.hooksPath`
- When to reach for a manager like **husky** or **lefthook**

## When to use it

Reach for hooks whenever you want a check to run consistently and locally before
code leaves a developer's machine: blocking commits with lint errors, rejecting
non-conventional commit messages, or running a quick test suite before a push.
