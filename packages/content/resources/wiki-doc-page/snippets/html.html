Querying with the SDK

Run reads against an Aurora DB cluster from the official client. This page covers single-statement queries, parameter binding, typed result rows, and the cursor API used by Project Nimbus for large exports.

Updated Jun 8, 2026 5 min read Stable

Overview

The query() method sends a statement to the primary node and returns a typed result set. Statements are parsed once and cached per connection, so repeating a query with different parameters reuses the prepared plan. For workloads that read more than a few thousand rows, prefer the cursor API so results stream instead of buffering in memory.

Note

All queries run against the nearest healthy replica unless you set { consistency: "strong" }, which routes to the primary.

Install

Add the client to your project. The SDK ships ESM and CJS builds and has zero runtime dependencies.

# install the CLI + client
npm install @auroradb/client
aurora login --profile prod
npm install @auroradb/client
// or with bun
bun add @auroradb/client
pip install auroradb
# optional: async extras
pip install "auroradb[async]"

A basic query

Connect, then call query() with a parameterized statement. Positional parameters ($1, $2) are bound server-side, so user input is never concatenated into SQL. The example below fetches active members of the Verdant Empire tenant. 

curl https://api.auroradb.dev/v4/query \
  -H "Authorization: Bearer $AURORA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"sql":"select id, name from member where tenant = $1 and active","params":["verdant"]}'
import { connect } from "@auroradb/client";

const db = await connect(process.env.AURORA_URL);

const { rows } = await db.query(
  "select id, name from member where tenant = $1 and active",
  ["verdant"],
);

for (const m of rows) console.log(m.id, m.name);
import auroradb

db = auroradb.connect(os.environ["AURORA_URL"])

rows = db.query(
    "select id, name from member where tenant = $1 and active",
    ["verdant"],
)

for m in rows:
    print(m["id"], m["name"])

Avoid string interpolation

Never build SQL with template strings. Always pass values through the params array — the planner binds them as typed literals and rejects injection attempts.

Typed rows

Each row is a plain object keyed by column name. Pass a type parameter to get full editor autocomplete on the returned shape. Columns map to their nearest host type — timestamptz becomes a Date, jsonb is parsed, and numeric stays a string to preserve precision.

Aurora typeJS typeNotes
int8number / bigintbigint past 2⁵³
numericstringlossless decimal

Streaming with cursors

For large result sets, open a cursor and iterate. Rows arrive in batches of fetchSize (default 500) and the connection stays pinned until the cursor is drained or closed. This keeps memory flat regardless of how many rows match.

“Cursors are the difference between exporting a million rows and crashing a pod. Use them.” — Aurora DB field guide

const cur = db.cursor("select * from event order by ts", [], {
  fetchSize: 500,
});

for await (const row of cur) {
  await sink(row); // backpressure-aware
}
with db.cursor("select * from event order by ts", fetch_size=500) as cur:
    for row in cur:
        sink(row)  # streamed batch by batch

Tip

Wrap a cursor in a transaction with { isolation: "repeatable read" } to get a stable snapshot across the whole export.

Error handling

Failed queries throw an AuroraError with a stable code you can switch on. Network faults are retried automatically up to maxRetries; only logical errors surface to your code.

  • 23505 — unique violation
  • 40001 — serialization failure (safe to retry)
  • 57014 — statement timeout
  • 53300 — too many connections
