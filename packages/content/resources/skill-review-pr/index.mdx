# PR Review Checklist

A concise, copy-pasteable reference for reviewing pull requests well. It walks
through what to look for — correctness, tests, security, readability, scope, and
naming — and how to phrase feedback so it is kind, specific, and actionable.

## What this skill is

A structured checklist you can run top-to-bottom on any pull request so nothing
important slips through, plus a small vocabulary (nit, suggestion, blocking) for
communicating severity clearly.

## When to use it

Reach for it whenever you open a teammate's PR, before approving your own changes
after self-review, or when onboarding new reviewers who want a consistent bar.

## Where the full cheatsheet lives

The complete checklist, conventional comment prefixes, and end-to-end review
workflows are in the snippet: `snippets/markdown.md`. Copy it into your repo or
team wiki and adapt the bars to your project.
