Aurora DB REST API

The Aurora DB API lets you provision distributed clusters, manage point-in-time snapshots, and inspect replica health over plain HTTPS. Every response is JSON, every request is authenticated with a secret key, and all timestamps are RFC 3339 UTC.

The API is organized around resources. Predictable, resource-oriented URLs accept form-encoded request bodies, return JSON-encoded responses, and use standard HTTP verbs, authentication, and status codes. The current stable version is v3; the base URL is:

i
Base URL. https://api.auroradb.dev/v3 — all requests must be made over HTTPS. Calls over plain HTTP will fail.

Authentication

Authenticate by passing your secret key in the Authorization header as a bearer token. Keys are scoped to a single project and carry the live or test prefix. Never embed a secret key in client-side code.

Authorization: Bearer ak_live_7Qm3…f2Vd
GET /v3/clusters #

List clusters

Returns a paginated list of clusters owned by the authenticated project, most recently created first. Use the region and status query parameters to narrow results.

Query parameters

NameTypeReq.Description
regionstringoptionalFilter by deployment region, e.g. us-east-1 or eu-west-3.
statusenumoptionalOne of provisioning, active, degraded, archived.
limitintegerrequiredPage size between 1 and 100. Defaults to 20 when omitted on the first page.
starting_afterstringoptionalCursor for pagination — the object ID that defines your place in the list.

Responses

  • 200 A paged list object with a data array of clusters.
  • 401 Missing or invalid API key.
  • 422 The limit parameter is out of range.
POST /v3/clusters #

Create cluster

Provisions a new Aurora DB cluster in the requested region. The call returns immediately with a cluster in the provisioning state; poll Retrieve cluster until status becomes active.

Body parameters

NameTypeReq.Description
namestringrequiredHuman-readable name, 1–48 characters. Must be unique within the project.
regionstringrequiredTarget region. See supported regions.
tierenumoptionalCompute tier: nimbus, verdant, or aurora. Defaults to nimbus.
replicasintegeroptionalNumber of read replicas, 0–8. Defaults to 2.
encryptionbooleanoptionalEnable at-rest encryption with a managed key. Defaults to true.

Responses

  • 201 The newly created cluster object.
  • 409 A cluster with that name already exists.
  • 422 Validation failed on one or more fields.
  • 503 The region is at capacity; retry with backoff.
GET /v3/clusters/{id} #

Retrieve cluster

Fetches the details of an existing cluster, including live replica health and the most recent snapshot. You only need to supply the unique cluster ID returned on creation.

Path parameters

NameTypeReq.Description
idstringrequiredThe cluster ID, e.g. clu_8Kdb20fA.
expandarrayoptionalExpand nested objects, e.g. replicas, latest_snapshot.

Responses

  • 200 The requested cluster object.
  • 404 No cluster matches that ID for this project.
DELETE /v3/clusters/{id} #

Delete cluster

Permanently deletes a cluster and all of its read replicas. Snapshots are retained according to your project's retention policy. This action cannot be undone.

!
Destructive. Deletion is irreversible. Take a final snapshot first if you may need the data later.

Path parameters

NameTypeReq.Description
idstringrequiredThe ID of the cluster to delete.

Responses

  • 200 A deleted confirmation object.
  • 404 The cluster does not exist.
  • 409 The cluster has an in-flight snapshot; retry shortly.

Errors & status codes

Aurora DB uses conventional HTTP response codes. Codes in the 2xx range indicate success; 4xx codes indicate a problem with the supplied information; and 5xx codes indicate a server-side error.

CodeMeaning
400Bad request — often a malformed body.
401Unauthorized — no valid API key provided.
429Too many requests — see rate limits.
500Something went wrong on Aurora DB's end.

Pagination

All list endpoints support cursor-based pagination via limit and starting_after. Each list response includes a has_more boolean and the ID of the last object, which you pass back as the next cursor.

Rate limits

The API allows up to 100 requests per second per project in live mode. Responses include X-RateLimit-Remaining and X-RateLimit-Reset headers. Exceeding the limit returns 429; back off using the reset header.
