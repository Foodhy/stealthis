Cluster topology

Aurora DB organizes nodes into a single logical cluster split across regions. This page explains how the control plane, coordinator nodes, and storage replicas fit together, and how the topology changes when you scale Project Nimbus deployments.

A cluster is the unit of failure isolation in Aurora DB. Every cluster runs an odd number of coordinator nodes that participate in the Raft-based control loop, plus any number of stateless gateway nodes and durable storage replicas. The coordinators elect a leader; the leader owns the routing table.

Replication factor

By default each shard is replicated RF=3 across distinct availability zones. Writes are acknowledged once a quorum of replicas has persisted the entry to its write-ahead log. You can raise the replication factor per keyspace for hot data: 

ALTER KEYSPACE verdant
  WITH replication = { 'class': 'ZoneAware', 'rf': 5 };

Note — Increasing the replication factor improves durability but raises write amplification. Plan storage for roughly rf × dataset before enabling.

Consistency model

Aurora DB offers tunable consistency. The table below summarizes the read/write level pairs that guarantee read-your-writes within the Verdant Empire region set.

Write levelRead levelGuarantee
QUORUMQUORUMStrong, read-your-writes
ALLONEStrong, slow writes
ONEONEEventual, lowest latency

Caution — Mixing ONE/ONE with multi-region clusters can surface stale reads for up to one gossip interval. Pin latency-sensitive paths to QUORUM.

Rolling upgrades

To move a cluster from one minor version to the next, drain one coordinator at a time using aurora node drain, wait for the leader to re-stabilize, then rejoin. The control plane keeps the cluster writable throughout.

Tip — Use the version switcher above to compare these instructions against an older release line — the drain command changed in v3.0.

When all coordinators report the new build hash, the upgrade is complete and the compatibility window closes automatically. See the operations runbook for the full checklist and rollback procedure.
