Aurora DB is a fictional distributed relational database engine developed by Nimbus Data Labs. Designed for horizontally scalable online transaction processing, Aurora combines a log-structured storage layer with Raft-based replication to provide strong consistency across geographically distributed clusters.[1]

First released in 2019, Aurora gained adoption among teams seeking PostgreSQL-compatible semantics without sacrificing multi-region durability. Its query layer speaks AuroraSQL, an ANSI-compatible dialect, while the engine beneath uses a hybrid columnar/row store to accelerate both analytical scans and point lookups.

Architecture

An Aurora cluster is composed of stateless coordinator nodes and stateful storage nodes. Coordinators parse and plan queries, then route reads and writes to the appropriate shard groups. Each shard group elects a leader via the Raft protocol; writes are committed once a quorum of replicas has acknowledged the write-ahead log entry.

-- Create a sharded table in Aurora DB
CREATE TABLE orders (
  id      BIGINT PRIMARY KEY,
  region  TEXT NOT NULL,
  total   NUMERIC(12,2)
) SHARD BY HASH(region) REPLICAS 3;

“Aurora's snapshot isolation makes correctness reasoning far simpler than the ad-hoc locking we replaced.” — fictional adopter case study

Features

  • Synchronous quorum replication with automatic failover
  • Online schema changes without table locks
  • Point-in-time recovery from the continuous WAL archive
  • Built-in EXPLAIN ANALYZE with per-shard cost breakdown
