OAuth 2.0 authorization

Authorize third-party applications against an Aurora DB workspace using the OAuth 2.0 authorization-code flow with PKCE. This page covers the grant lifecycle, scope model, and token exchange endpoints exposed by the Verdant identity service.

Aurora DB delegates external authentication to Verdant, the platform identity service shared across Project Nimbus deployments. An application registers a client, requests a set of scopes, and redirects the user to the Verdant consent screen. After consent, Verdant returns a short-lived authorization code that the client exchanges for an access token and a refresh token.

We strongly recommend the authorization-code flow with PKCE for every client type, including single-page and native apps. The implicit flow is deprecated and will be removed in v5.0.

Authorization-code flow

A typical exchange looks like the following. The code_verifier is generated by the client and never leaves the device until the token exchange step. 

POST /oauth/token HTTP/1.1
Host: auth.verdant.dev
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=ac_9f2c41be
&redirect_uri=https://app.example.com/callback
&client_id=cli_nimbus_42
&code_verifier=dBjftJeZ4CVP-mB92K27uhbUJU1p1r

Scope model

Scopes are namespaced by resource. Request the narrowest set your integration needs — Verdant surfaces every requested scope on the consent screen, and over-broad requests reduce install conversion.

ScopeGrantsTier
db.readRead rows from tables and viewsStandard
db.writeInsert, update, and delete rowsStandard
schema.manageCreate or alter tables and indexesElevated
secrets.readRead connection secrets and keysRestricted

Note — Restricted scopes require workspace-owner approval and are audited. Press R in the dashboard to open the request log.

Refreshing tokens

Access tokens live for one hour. Use the refresh token to mint a new pair without prompting the user again. Refresh tokens rotate on every use — store only the latest value and discard the previous one to keep your client within the replay window.
